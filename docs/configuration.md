# Configuration

> [!note] Planned
> This describes the layout PLAN-00001 delivers, matching
> passalong-android's; nothing is written yet.

The app keeps everything in its sandbox's Application Support directory
(`Library/Application Support/`), readable by the app only and excluded
from iCloud and device backups. There are no settings outside it.

| File | What it is |
|---|---|
| `config.toml` | The core's config, written by the setup screen in the format `passalong init` writes; every key is documented in [passalong's configuration doc](https://github.com/joelee/passalong/blob/main/docs/configuration.md) |
| `keys/id_ed25519`, `keys/id_ed25519.pub` | This device's identity for an SSH server, generated by the app; the public key goes into the server's `authorized_keys` |
| `api.key` | This device's API key for a passalong-server (`pal_<id>_<secret>`), readable by the app alone, named in `server.https.api_key_file` |
| `list-cache.json` | The list cache, as `serve` keeps it on desktops |
| `Downloads/` | Staging for downloads: the core writes a verified file here, the app moves it to the app's Documents folder, which the Files app shows as *On My iPhone › Passalong* |
| `.config/passalong/store.key` | Where the core would keep an encrypted store's key (`client.key_file`); not written, since joining an encrypted store is not implemented |

As on Android, the core sees the Application Support directory as
`HOME`, so the paths in the config are the ones `passalong init` would
write on a desktop, expanded under the app's storage.

The setup screen fills the same fields as passalong-android's
([its configuration doc](https://github.com/joelee/passalong-android/blob/9c2bf5974630237fd4a0b28472afadc7a488c8da/docs/configuration.md)),
with the device name defaulting to the device's model (`iPhone`), since
iOS no longer reveals the user-assigned name without an entitlement.

## Secrets

The identity key has no passphrase and never leaves the sandbox. Files
are written with `NSFileProtectionCompleteUntilFirstUserAuthentication`.
The API key is typed into a secure field, kept in memory only until the
setup completes, then in `api.key`; it never appears in the config, in
logs, or in the list cache.

## Logging

The core's records go to the unified log, subsystem
`io.github.joelee.passalong`, category `passalong`, at level `debug` in
debug builds and `info` otherwise. Watch them in Console.app, or with
`xcrun simctl spawn booted log stream --predicate 'subsystem ==
"io.github.joelee.passalong"'`. Pasteboard text, file contents, keys, and
secrets are never logged.
